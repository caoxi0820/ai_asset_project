# 方案 1：国内基金 / QDII / 低成本部署蓝图

## 1. 方案定位
这套方案适合：
- 你主要分析 **中国公募基金**、**QDII 基金**；
- 希望尽量使用 **免费开源工具**；
- 可以接受部分数据源偶尔抖动、字段风格不完全统一；
- 你更关心“尽快搭起来并能持续用”。

## 2. 组件组成（简单解释每个工具做什么）

### A. `AKShare`
作用：
- Python 数据源库。
- 提供 A 股、基金、ETF、港美股部分行情、基金净值、基金档案、持仓、行业数据等。
- 在这个方案里，它是 **最核心的免费数据底座**。

### B. `FundSeeker`
作用：
- 更偏向“基金分析”的开源项目。
- 适合补充基金筛选、基金基本分析逻辑和一些现成的视角。
- 在这个方案里，它负责 **把纯数据变成更像基金研究的结构化分析**。

### C. `AKTools` / `AKShare MCP Server`（任选一种包装层）
作用：
- 把 `AKShare` 包装成 ChatGPT/Codex 更容易调用的工具层。
- 这样 AI 不用自己写很多数据抓取代码，而是像调用一个“数据工具箱”。
- 在这个方案里，它负责 **把数据查询能力暴露给 ChatGPT/Codex**。

### D. `持仓解析 + 报告生成 skill`
作用：
- 解析你给 AI 的自然语言持仓。
- 例如：`我持有 5000 份 161725，成本价 1.423，当前浮亏 320 元`。
- 将它转成结构化对象，然后交给数据层和分析层继续处理。
- 最终根据查询结果生成 **持仓诊断报告**。

## 3. 免费 / 成本说明
- `AKShare`：免费。
- `FundSeeker`：开源免费。
- `AKTools` / 自建 MCP 包装层：开源免费。
- 运行成本：主要是你自己电脑上的 Python 环境和少量本地资源占用。
- **这套方案默认不要求付费 API Key。**

## 4. 这套方案解决什么问题
它重点解决：
- 某只基金当前值不值得继续持有；
- 你手里几只基金之间是否高度重合；
- QDII 基金底层主要暴露哪些区域 / 行业 / 美股资产；
- 当前组合是否过于集中在某个风格、行业、市场；
- 从持仓成本和当前净值角度，给出组合风险提示。

## 6. 自动化部署边界

### 可以让 ChatGPT/Codex 自动完成的部分
- 创建目录结构；
- 创建 Python 虚拟环境；
- 安装 Python 依赖；
- 拉取开源仓库；
- 生成本地 skill 模板；
- 生成持仓解析脚本、报告模板、统一入口脚本；
- 配置 ChatGPT Desktop / Codex 需要的本地 MCP 启动命令（如果你的本地环境支持）。

### 你需要人工参与的部分
- 确认目标目录；
- 确认 Python 版本；
- 若某个开源项目安装失败，允许 ChatGPT/Codex 替换为兼容实现；
- 首次手工验证 1~2 个基金代码是否能拉到数据。

## 7. 部署后的链路是怎么工作的
1. 你在 ChatGPT Desktop 里说：
   - `我持有 5000 份 161725，成本价 1.423，当前浮亏 320 元，请分析是否应该继续持有。`
2. 持仓解析 skill 会把这句话转成：
   - 基金代码：`161725`
   - 持仓份额：`5000`
   - 成本价：`1.423`
   - 当前总浮亏：`320`
3. MCP 工具去查：
   - 基金名称、类型、近一年净值曲线、回撤、基金经理、季报持仓、行业暴露、同类比较。
4. 基金分析模块把这些信息和你的持仓结合起来。
5. 最后输出一份报告，例如：
   - 当前盈亏定位；
   - 风险来源；
   - 与你其它基金的重仓重合；
   - 继续持有 / 观察 / 分散风险的建议。

## 8. 报告建议结构
建议让部署后的系统统一输出以下结构：
1. 结论摘要
2. 持仓概况
3. 基金画像
4. 净值 / 回撤 / 波动分析
5. 持仓行业与资产暴露
6. 与已有持仓的重合度分析
7. 风险提示
8. 可执行建议（不是机械买卖建议，而是观察点）

## 9. 可直接喂给 ChatGPT/Codex 的部署指令
把下面整段原样贴到另一台电脑的 ChatGPT/Codex：

```text
你现在是我的本地部署助手。请在这台电脑上为我部署一个“国内公募基金 / QDII 基金低成本分析工作台”，部署目录默认使用 ~/finance-agents/cn-fund-low-cost 。

目标：
1. 使用 Python 虚拟环境部署。
2. 尽量使用开源免费工具，优先使用 AKShare 作为数据源。
3. 优先接入一个 AKShare 的 MCP 包装层；如果现成 MCP 项目不可用，就在本地实现一个最小可用 MCP/CLI 数据代理，至少支持：
   - 基金基础信息查询
   - 基金净值历史查询
   - 基金阶段涨跌幅查询
   - 基金持仓/行业暴露查询（能拿到多少算多少）
   - QDII 基金基础资料查询
4. 集成一个偏基金分析的本地分析模块；如果 FundSeeker 能稳定安装就集成，否则自行实现一个“基金报告生成器”，输出 markdown 报告。
5. 创建一个持仓解析模块，要求能解析如下自然语言：
   - 我持有 5000 份 161725，成本价 1.423，当前浮亏 320 元
   - 我持有 2000 份 000457，成本价 1.02，当前盈利 180 元
   并转成结构化 JSON。
6. 创建一个统一入口脚本，例如 `analyze_portfolio.py`，允许输入自然语言持仓和问题，输出 markdown 报告到 reports/ 目录。
7. 创建 README、env.example、示例持仓文件、示例问题文件。
8. 若某一步依赖安装失败，不要中止，先给出替代方案并尽量自动修复。
9. 部署完成后，帮我做一次验收：
   - 用 161725 或任意可用基金代码跑一次；
   - 输出一份示例报告；
   - 告诉我以后在 ChatGPT 里应该如何调用它。

限制与要求：
- 不要依赖付费 API。
- 不要要求我提供交易流水。
- 持仓输入只假定我会提供：基金代码、持有份额、成本价、当前总盈亏。
- 报告必须同时结合“市场数据 + 当前持仓成本/盈亏”来分析。
- 先检查本机是否已有 Python3、uv 或 pip；缺什么补什么。
- 优先自动完成，只有遇到必须人工处理的步骤时再问我。

请按以下顺序执行：
A. 检查环境
B. 创建目录和虚拟环境
C. 安装依赖
D. 接入数据源与 MCP
E. 生成持仓解析与报告模块
F. 生成示例与文档
G. 跑一次验收
H. 给我最终使用方法
```

## 10. 验收清单
部署完成后，至少要验证：
- 能根据基金代码查到基金名称；
- 能查到近期净值；
- 能把自然语言持仓转成 JSON；
- 能输出一份 markdown 报告；
- 报告中能体现你的持仓成本和当前盈亏，不只是市场数据摘要。

## 11. 风险与限制
- 免费数据源字段可能不稳定；
- 个别 QDII 基金的穿透持仓可能不完整；
- 免费方案更适合“辅助分析”和“持仓体检”，不适合做高频、严格量化交易决策；
- 输出必须附带“非投资建议”提示。
